## S03 — Audit decision record

Recommendation: retain the single-builder architecture. The Main Codex should
obtain work only through:

1. `builder-claim --model gpt-5.6-luna --batch-id ARCHON-V3-TRIAL-020`;
2. implementation or bounded audit work in the returned isolated worktree;
3. focused tests and a real candidate commit;
4. `builder-submit` with the exact candidate/base/lease metadata; and
5. the systemd-controlled independent `qc-merge` lane.

The old autonomous `run` and recovery-coding paths must remain disabled. A
candidate passing QC is not complete until the serialized Merger integrates it
and the Master records all child receipts.

Rejected alternatives:

- launching the former W1–W5 or R1/R2 coding workers;
- starting a second Master or task database;
- treating a task row or a candidate submission as completion;
- clearing owner, STOP, PAUSE or quota controls to force a claim; and
- changing the task plan to hide the audit report's documentation scope.

The minimal runtime correction is to honor the explicit bounded documentation
allowance for `audit` and `design` packets even when their suggested source
roots omit `docs/`. Executable, source, generated and protected paths remain
rejected. The correction is covered by the Linux SDA regression test and the
release manifest.
