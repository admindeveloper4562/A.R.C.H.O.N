## Current implementation inventory

`DocumentStore` provides bounded SQLite FTS5 documents with source ID, URI,
scope, observation time, citation and content SHA-256. Replaying the same
document identity with the same content is idempotent; changing its content or
provenance is rejected as an identity conflict. Different document IDs are not
implicitly deduplicated.

`VideoResearchStore` and `InstagramReelStore` use `(media_id, observed_at)` as
their immutable observation identity. Replaying an identical observation is
ignored; a later observation is retained as history rather than incorrectly
discarded. `MediaRAGStore` uses stable content-derived chunk and summary IDs,
so repeated indexing of the same source does not create duplicate chunks or
summaries.

`SourceComparator` groups claims by normalized subject and emits source IDs,
citations and `source_id:citation` evidence references. Contradictions become
`uncertain` with no invented confidence. This supplies in-memory provenance
links, but it does not persist claim nodes or edges between related claims.

## Minimal decision contract

If the graph is implemented later, it should be additive and reuse existing
source evidence:

1. Canonical source identity must include source ID, citation/URI and content
   hash; observation time remains history, not identity.
2. Exact replay is idempotent; changed content at the same identity is a
   conflict, not an overwrite.
3. Claim nodes retain `fact`, `inference` or `uncertain` and point to one or
   more immutable evidence references.
4. Related-claim edges must be deterministic and queryable without granting
   retrieved content permission to perform actions.
5. No network fetcher, credentials, raw model transcript or automatic handbook
   write belongs in this scope.
