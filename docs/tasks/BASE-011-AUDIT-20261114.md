## S03 audit / decision record

Recommendation: keep BASE-011 `NOT_VERIFIED` until an implementation-level approval boundary and independent regression receipt exist. The next bounded implementation should add or explicitly approve the artifact locations for per-file deletion receipts and repository ownership enforcement, then add tests that bind approvals to exact action scope, content digest, actor, expiry, and idempotency key. It must preserve worker/QC/Merger separation and must not change `AGENTS.md` or `SECURITY.md` as a shortcut.

Required regression plan (to be run by an independent QC lane, not this audit):

1. Run targeted bootstrap tests: `python3 -m unittest discover -s bootstrap/astra-one/tests -p 'test_*.py'`.
2. Run repository tests covering policy, monitor redaction, queue state, and handoff: `python3 -m unittest discover -s tests -p 'test_*.py'`.
3. Add/run deletion cases for exact per-file approval, protected policy files, symlink/traversal, staged/unstaged changes, bulk mismatch, restart, and append-only receipt recovery; assert no delete occurs without approval.
4. Add/run secret cases using a non-sensitive canary: task schema, prompt, environment, exception, event/dashboard, and artifact paths; assert the canary is absent from emitted material and rejected from task payloads.
5. Add/run external-action cases for missing, expired, wrong-scope, wrong-digest, duplicate, replayed, timed-out, STOP, PAUSE, quota, and restart conditions; assert no side effect before authorization and exactly one effect after a valid idempotent approval.
6. Run `git diff --check`, inspect changed paths, and obtain an independent review receipt bound to the candidate SHA and test artifact hashes. Do not interpret mock-only or model-generated output as completion.

Rejected alternatives:

- Treating policy prose or the existing static deletion check as proof that arbitrary filesystem deletion is controlled.
- Treating rejection of a `secrets` task field as proof that OS credentials, logs, prompts, subprocesses, and Cloudflare events are leak-free.
- Treating a QC flag or worker instruction as owner authorization for an external action.
- Adding a blanket or bulk deletion approval to satisfy coverage; policy requires per-file authorization.
- Substituting the observed architecture digest for the supplied approved digest.
