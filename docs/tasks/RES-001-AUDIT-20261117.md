## Current implementation inventory

`DocumentStore` in Backend already persists and searches bounded documents with
`source_id`, `source_uri`, `access_scope`, `observed_at`, `citation`, title,
content SHA-256 and bounded metadata. It uses SQLite FTS5, rejects oversized or
malformed content, enforces scope-filtered search and preserves idempotent
document identity.

`OwnerIntentRouter` in Core provides bounded task intent, risk classification,
approval binding and queue admission. It is a general owner-intent boundary;
it is not a Research source allowlist and does not authorize network retrieval.

The Research module has no source adapter, citation type, job schema, source
allowlist, permission scope, network policy, or research-specific tests. The
legacy repository contains general provenance and sandbox concepts, but no
verified ARCHON Research implementation was copied or promoted.

## Required contract

The smallest compatible Research contract should be additive and reuse
`DocumentStore` for indexed evidence:

| Record | Required fields | Boundary |
| --- | --- | --- |
| `ResearchSource` | source ID, URI, title, observed timestamp, citation, access scope, content SHA, license/access note | Metadata and content are source-bound; URI is not permission |
| `ResearchJob` | job ID, requested scope, source allowlist, query, requester, correlation ID, status, created timestamp | Only explicitly allowlisted sources may be considered; external content is untrusted |
| `ResearchFinding` | finding ID, job ID, source ID, citation, claim kind (`fact`, `inference`, `uncertain`), confidence, evidence reference | Every claim must retain provenance and uncertainty |

Permission decisions must remain separate from source content. A future
network adapter must require an explicit module scope and owner-approved
configuration; it must not treat a URL, citation, model output or retrieved
document as authorization. Unsupported sources must fail closed and preserve a
bounded reason.

## Recommendation

job-scope and allowlist boundary, reuse Backend retrieval, add negative tests

store raw credentials or infer permission from retrieved content.
