## Current ARCHON inventory

The current Runtime tree contains `service.py`, `security.py`, `chat.py` and
`offline.py`. The existing Runtime service handles authenticated task/event
operations and owner-session security; the chat services stream text and
explicitly pause when an authorized model/adapter is unavailable. No current
Runtime symbol implements microphone capture, STT, wake-word detection,
push-to-talk state, quiet-hours policy or audio processing state.

The current web surface has a static `/voice` dashboard route. Its text says
voice remains disabled until a local adapter is configured. `apps/web/server.py`
is a loopback-only static server and exposes no `/api/voice` endpoint. The
existing Runtime security header sets `microphone=()` in `Permissions-Policy`;
this is browser hardening, not an implemented consent or capture workflow.

Existing dashboard tests verify bounded static routes, known assets and browser
headers. They do not claim voice hardware, STT, quiet-hours or processing-state
acceptance.

## Host/device evidence

The host has ALSA capture devices and PipeWire sources. The read-only checks
reported `arecord -l`, `pactl list short sources` and `wpctl status` successfully;
the available sources included the USB PnP Audio Device, built-in analog audio

This proves host enumeration only. It does not prove browser permission,
capture correctness, STT model availability, wake-word behavior, quiet-hours
enforcement, privacy retention behavior or an accepted real-device recording.
No audio was recorded or transmitted by this audit.

## Required implementation gate

The next Runtime implementation candidate should define and independently test a
small, explicit state contract rather than copy the legacy server:

`idle -> permission_required -> ready -> capturing -> processing -> idle`

with explicit `paused_quiet_hours`, `cancelled` and `error` outcomes. It must
bind permission and processing state to the visible UI, avoid retaining raw
audio by default, support cancellation, keep local-only behavior explicit and
leave wake-word support disabled until a separately authorized adapter exists.
The implementation must use the existing Runtime security boundary and must be
followed by real browser/device qualification; Linux enumeration alone cannot
satisfy that gate.
