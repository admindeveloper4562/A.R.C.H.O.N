## Scope and acceptance

The task asks for an audit of bounded local desktop application launch and
inventory actions. Its acceptance requirement is: **allowed applications only;
audit and confirmations enforced**. The four ordered children are inspection,
analysis, report recording and independent cross-checking. This task is an
audit, not permission to add an implementation that is absent from the current
runtime.

## Current ARCHON implementation

The pinned integration tree contains:

- `apps/desktop/` with only `.gitkeep`; no desktop action adapter or registry.
- `src/jarvis_v2/runtime/` with service, security, chat, offline and speech
  services, but no launch, inventory or desktop-action service.

The existing authorization and effect primitives are reusable foundations, but
they are not currently connected to a desktop launch or inventory operation.

## Host capability observation

The host exposes Wayland/Hyprland and common desktop helpers including

not acceptance evidence. No application was launched, no inventory scan was
performed and no external state was changed.

## Required implementation gate

The next implementation task should add the smallest bounded runtime boundary
that:

1. accepts a fixed application identifier, never an arbitrary shell command;
2. resolves that identifier through an explicit allowlist;
3. requires a fresh owner confirmation/capability for launch;
4. prepares and finalizes the effect through `EffectJournal`;
5. records a bounded, redacted audit receipt with an idempotency key; and
6. exposes only read-only, owner-selected, bounded inventory metadata with
   symlink and path-boundary checks.

Destructive file operations, unrestricted process execution, implicit root
selection and host-wide scans are outside this task's acceptance scope.
