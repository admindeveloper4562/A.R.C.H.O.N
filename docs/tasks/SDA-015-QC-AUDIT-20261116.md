## S03 — Decision record

Recommendation: retain the Main Codex → Master submission → independent QC →
serialized Merger workflow. The smallest required trust boundary is already in
place: malformed child evidence is rejected before queue mutation, deterministic
tests run before any optional model review, and only an approved candidate may
enter serialized integration.

The previous SDA-013 rejection exposed the practical failure mode: a candidate
could reach QC with summary evidence instead of one bounded record per child.
SDA-014 moved that check to the submission boundary and added a regression test.
That correction is present in the current integration baseline.

During this audit, the candidate worktree also reproduced a separate baseline
discrepancy: its older validator applied `suggested_scope_roots` before the
explicit audit-document allowance and rejected this required `docs/` report as
`unsafe_changed_path: outside_task_scope`. The active Main Codex controller
contains the reviewed ordering correction in `a58d173` (`fix(sda): honor audit
documentation scope [SDA-002]`), but that controller change is not part of this
report-only candidate. It must be reconciled through the normal reviewed
integration path before an old runtime is used to admit another audit report.

Rejected alternatives:

- treating a successful builder process as QC approval;
- treating a candidate submission as completion;
- allowing QC to edit source or waive child evidence;
- running hosted CI while its quota is exhausted;
- launching former autonomous coding workers or a second Master; and
- storing unbounded review text in task events.

Known limits remain explicit: provider quota and maximum capacity are not
inferred from local test success, hosted-only checks remain deferred, and a real
hardware acceptance gate cannot be satisfied by a Linux container.
