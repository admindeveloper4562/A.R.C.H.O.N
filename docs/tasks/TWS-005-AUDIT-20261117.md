## Decision

State: **AUDIT_COMPLETE_WITH_IMPLEMENTATION_GAP**.

The current TWS data layer safely bounds and fingerprints proof payloads, but
the acceptance clause is not fully implemented. A proof's existence is enough
for the current quest transition to `verified`; there is no TWS-owned privacy
scope on a proof and no reward gate that requires an independently accepted
review. This report records the gap without changing the inspected source.

## S02 — Acceptance findings

| Acceptance clause | Finding | Evidence / gap |
|---|---|---|
| Unverified evidence never yields XP | **Not verified** | The store has `review_state`, but no review operation or reward ledger is exposed. `transition_quest(..., "verified")` checks only that a proof exists, so a `submitted` proof can reach `verified`. |
| Privacy scopes enforced | **Not verified** | TWS proof schema has no privacy-scope column and `append_proof` accepts no scope. Backend privacy labels exist but are not connected to proof capture or review. |
| Evidence is bounded and replay-safe | **Verified for current layer** | Canonical JSON, size bound, SHA-256 identity and a unique `(quest_id, evidence_sha256)` index prevent duplicate submissions and unbounded payloads. |
| Invalid references fail closed | **Verified for current layer** | Unknown wings and quests are rejected; lifecycle transitions are constrained and terminal states cannot be rewritten. |

## S03 — Decision and next implementation boundary

Do not claim TWS-005 feature acceptance from the current source. The smallest
follow-up implementation should:

1. bind every proof to an allowed privacy scope;
2. provide an independently controlled review transition to `accepted` or
   `rejected`;
3. require an accepted proof before `verified` and before any XP/reward effect;
4. preserve append-only proof history and idempotent review retries; and
5. add focused negative tests for unreviewed proof, rejected proof, invalid
   scope and cross-scope access.

The XP ledger and exactly-once reward receipt remain the scope of TWS-006. This
audit does not add a competing implementation or alter the task ledger.
