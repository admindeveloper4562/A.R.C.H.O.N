## Scope and acceptance

The task audits the requirement to preserve metadata-only file inventory, repo
discovery and FTS search. Its acceptance is: **read-only defaults and bounded
roots prevent private data exfiltration**. The four ordered children require
inspection, comparison, a versioned report and an independent cross-check. This
task is audit-mode; it records implementation evidence and gaps rather than
adding a new inventory runtime.

## Current ARCHON implementation

The pinned ARCHON tree contains:

- `apps/web/server.py` serving the static dashboard shell. The `/files` page
  describes bounded metadata but the current web server has no live filesystem
  inventory API.
- `src/jarvis_v2/backend/code_index.py` providing bounded source indexing and
  FTS search. This is a source-code index, not an owner-selected filesystem
  metadata inventory.
- `src/jarvis_v2/backend/context.py` enforcing restricted fields before data
  can enter a context packet.
- `src/jarvis_v2/runtime/browser.py` providing separate browser profile and
  typed-action boundaries. It does not scan local filesystem roots.

No current ARCHON module owns scan-root persistence, bounded filesystem
metadata records, repository discovery or inventory FTS tables. No host scan
was run during this audit.

## Required implementation gate

The next implementation task should add a module-owned inventory boundary that:

1. persists only explicitly owner-selected roots;
2. rejects virtual, protected, symlinked and out-of-bound roots;
3. performs bounded metadata traversal with a clear incomplete result when the
   limit is reached;
4. records repository identity and metadata without reading file content by
   default;
5. provides bounded literal/FTS search over stored metadata; and
6. exposes previews/status only, with no delete, move, overwrite or implicit
   root selection.

The implementation should adapt the legacy algorithms to current ARCHON module
ownership and migration rules rather than importing the legacy server wholesale.
