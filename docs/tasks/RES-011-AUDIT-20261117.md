## Current implementation inventory

`GitHubSourceAdapter` accepts only an exact repository allowlist. Search results
are filtered to exact HTTPS GitHub repository URIs; commit inspection requires
a full pinned SHA, an allowlisted license and allowlisted paths. Protected paths
are rejected, command-like fields and execution requests are blocked, and
provider failures are reduced to bounded reasons. The adapter consumes injected
transport results and does not clone, execute or write source content.

The root handbook states that Research may propose cited development tips but
may not change safety policy, and that only independent review/Merger paths may
apply governed edits. `BASE-009-HANDBOOK-GOVERNANCE-DESIGN.md` specifies the
proposal, section ownership, QC, owner-gate and serialized-apply contract, but
explicitly says that implementation is not verified.

No runtime Research module imports a handbook writer or performs a write to
`CODING_HANDBOOK.md`. There is also no implemented Research trend/technique
advice object or proposal queue that turns a GitHub result into a handbook
candidate. This is the correct safety posture for the direct-write acceptance,
but it leaves the positive on-demand advice workflow unimplemented.

## Minimal decision contract

If the missing workflow is implemented later, it must:

1. Emit a bounded advice record containing repository, pinned commit, file/blob
   references, license, observation time, rationale and source citations.
2. Treat advice as an untrusted proposal; it must not edit the handbook or
   change permissions, tests, quota, STOP/PAUSE or approval policy.
3. Submit only through the BASE-009 proposal/QC/Merger workflow, binding the
   handbook base digest and the exact candidate digest.
4. Reject duplicate/conflicting proposal IDs and preserve rejected evidence.
5. Keep hosted GitHub Actions and arbitrary source execution out of scope.
